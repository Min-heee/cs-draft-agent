# 3차 평가: 2차 수정안 반영 + 가벼운 채점 (2026-10-21)

[2차 평가](EVAL-2.md)의 3차 프롬프트 수정안 1~4를 반영하고, 2차 초안을 비교 기준으로 16건을 다시 돌렸습니다.

- **결과 요약**: 실패 0건, 주요 이슈 0건입니다. 수정안 네 가지 중 셋은 의도대로 동작했습니다.
- **내부 메모 규칙**: 수정안 3번(내부 메모)은 프롬프트만으로는 한 건씩 빠져서 코드로 보장했습니다.
- **원본 데이터**: `data/eval-3-drafts.json`, `data/eval-3-judgments.json`, `data/eval-3.md`, `data/eval-3.db`

## 어떻게 돌렸나

평가 환경은 2차와 같습니다(`scripts/eval-inputs.ts`, [eval/workflow.js](../eval/workflow.js)). 이번에는 구독 사용량을 줄이려고 채점자를 문의당 1명으로 줄였습니다(`judges: "one"`).

- 채점자 한 명이 근거·안전·문체 세 기준을 함께 봅니다.
- 이번에 바꾼 3차 항목 4개는 따로 "충족/부분/미충족/해당 없음"으로 점검합니다.

| | 2차 (채점자 셋) | 3차 (채점자 하나) |
|---|---|---|
| 에이전트 | 64 | 32 |
| 걸린 시간 | 6분 4초 | 2분 18초 |
| 구독 사용량 | 약 443만 토큰 | 약 226만 토큰 |
| API 비용 | 0원 | 0원 |

**해석할 때 주의할 점**: 채점자가 하나라 판정 하나하나의 흔들림이 큽니다. 그래서 같은 채점자가 2차 초안도 다시 매기게 해서 비교했습니다. 그 결과(통과 33, 경미 13, 실패 2)가 2차의 채점자 셋 결과(통과 33, 경미 14, 실패 1)와 거의 같았습니다. 가벼운 채점도 쓸 만하다고 봅니다.

## 이번에 코드로 고친 것

- **승인 전 확인 항목 자동 추가** (`applyGuardrails`): 답변에 "첫 사이즈 교환" 혜택이 나오는데 내부 메모에 사용 이력 확인이 없으면 "[자동] 답변에 첫 사이즈 교환 무료를 안내함: 이 회원이 이미 썼는지 확인"을 덧붙입니다. 담당자 확인 사유는 아니고 승인할 때 볼 점입니다. 2차·3차 결과에 다시 적용하면 놓쳤던 두 건(1201, 1212)에만 붙습니다.
- **검토 화면의 내부 메모 줄바꿈**: 여러 줄 메모가 한 줄로 붙어 보이던 것을 고쳤습니다.

## 4차 후보

프롬프트 후보입니다. 남은 문제가 모두 경미해서 급하지 않습니다.

1. **할 수 없는 처리를 이미 했다고 쓰지 않기** (1210 "환불 요청으로 접수해 두었습니다")
   - 예: "접수 완료", "변경 완료".
   - 단, 게시판 글을 교환·반품 신청으로 인정하는지는 회사 정책으로 먼저 정해야 합니다(EVAL-1에서 지적).
2. **내부 사정(정책 문서, 도구)을 고객에게 설명하지 않기** (1213)
3. **담당자 확인에 필요한 자료 요청(주문번호, 사진)은 해도 된다고 명시** (1213)
   - "지어내지 말라"는 규칙이 자료 요청까지 막지 않게 합니다.
4. **내부 메모의 "언제까지"는 정책 기한이 있을 때만 요구하기** (부분 5건)
   - 지금처럼 늘 요구하면 기한을 지어낼 위험이 있습니다.
