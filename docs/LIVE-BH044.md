# 실제 카페24 연결: 테스트 쇼핑몰 bh044 (2026-10-27)

카페24에 테스트 쇼핑몰(bh044)을 만들어, 목업이 아니라 실제 카페24 Admin API로 처음 돌렸습니다. 고객 글은 모두 가짜 자료입니다.

## 연결

- **개발자센터 앱 "CS 답변 초안"**
  - 권한: 게시판 읽기·쓰기, 주문 읽기, 상품 읽기
  - Redirect URI: `https://bh044.cafe24.com`
- **토큰 받기**: bh044에 앱을 설치한 뒤 `scripts/cafe24-auth.ts`로 받았습니다.
  - `url`: 권한 동의 주소를 만듭니다.
  - `token <code>`: 돌아온 주소의 code로 토큰을 받아 `data/cafe24-token.json`에 저장합니다. 이 파일은 git에 올리지 않습니다.
  - `boards`: 게시판 목록으로 연결을 확인합니다.
- **게시판 번호**: 상품 Q&A는 6번, 상품 사용후기는 4번입니다. 목업은 Q&A를 4번으로 두었지만, 실제 쇼핑몰에서 4번은 후기 게시판이었습니다.
- **앱 내장 브라우저에서 생긴 일**: 내장 브라우저는 사이트의 알림창(alert)을 띄우지 않습니다. 그래서 개발자센터에서 "필수 입력 항목"(App URL)과 "저장되었습니다" 메시지가 보이지 않아, 저장이 안 되는 것처럼 보였습니다. 콘솔 기록으로 확인해 해결했습니다.

## 가짜 자료 올리기 (`scripts/seed-cafe24.ts`, `data/seed/bh044.json`)

- **상품 Q&A 16건**: 데모 문의 16건을 bh044의 샘플 상품 번호로 바꿔 올렸습니다(글 2, 4~18). 주입 지시 문의(1215)도 포함했습니다.
- **상품 후기 11건**: 칭찬, 사이즈·세탁·배송 불만, 불량, 전화번호가 적힌 후기, 관리자를 사칭한 주입 후기를 섞었습니다(글 3, 19~28).
- **실측표**: 샘플 상품에는 실측이 없어서 데모 실측표를 복사해 넣었습니다(`copied_from`).
- **한계**
  - API로 올린 글이라 회원·주문과 연결되지 않습니다.
  - 샘플 상품에는 사이즈 옵션과 재고 수량이 없습니다.
  - bh044는 누구나 들어올 수 있는 주소라, 가짜 글이 공개 게시판에 보입니다.

## 실제 API에서 처음 드러난 차이 (고침)

| 무엇 | 목업에서 가정한 것 | 실제 응답 | 고친 것 |
|---|---|---|---|
| 없는 주문번호 | 404 | `200 {"order":{}}` | 주문번호가 없으면 "주문 없음"으로 처리 |
| 옵션 없는 상품 | `options` 배열 | `options: null` | 빈 배열로 바꿔 둠 |
| 재고를 세지 않는 상품 | 수량 0 = 품절 | `use_inventory: "F"`, 수량 0 | "판매중(재고 수량을 관리하지 않는 상품)"으로 표시 |
| 사이즈 옵션 없는 상품의 사이즈 추천 | 사이즈별 재고로 걸러 냄 | 사이즈 옵션이 없음 | 추천은 하고, 재고는 "사이즈별 재고 정보 없음"으로 표시 |

첫 실행에서는 이 차이 때문에 상품 조회와 사이즈 추천이 계속 오류를 냈습니다. 고친 뒤 다시 돌렸을 때 남은 도구 오류는 2건뿐이었고, 둘 다 가짜 주문번호를 조회한 "주문 없음"이었습니다.

## 상품 후기 댓글 초안 (새 기능)

- **흐름**: 후기 게시판(`CAFE24_REVIEW_BOARD_NO`)의 글을 함께 불러와, 문의와 같은 검토 화면에 "후기 ★n"으로 보여 줍니다. 승인하면 답글이 아니라 댓글로 등록합니다.
  - 댓글 등록 코드는 아직 실제 쇼핑몰에서 한 번도 실행하지 않았습니다.
- **프롬프트 규칙("상품 후기에 다는 댓글")**
  - 2~4문장으로 쓰고, 고마움은 한 번만 말합니다. 고객이 말한 점을 되받습니다.
  - 정책에 없는 보상은 약속하지 않습니다.
  - 사이즈 불만에는 교환 신청 경로를 안내합니다. 후기 글은 교환·반품 신청이 아닙니다.
  - 불량·환불 요구는 확인 필요로 넘기고, 상품 Q&A 게시판에 사진과 주문번호를 남겨 달라고 안내합니다.
  - 후기에 적힌 개인정보는 댓글에서 되풀이하지 않습니다.
- **코드 규칙 추가**: 답변에 전화번호가 들어가면 확인 필요로 표시합니다. 주문번호와 송장번호는 표시하지 않습니다.
- **시험**: 90개가 통과합니다. 후기 저장·댓글 등록(목업), 예전 DB 이전, 화면, 프롬프트, 옵션 없는 상품, 전화번호를 다룹니다.

## 실제 등록 (대표 승인, 2026-10-27 15:04)

앱의 승인 경로(`Pipeline.review`)로 두 건을 실제 bh044에 등록했습니다.
- **Q&A #2 (사이즈 문의)**: 답글 #29 "RE: 사이즈 문의드려요"(작성자 CS팀)로 올라가, 게시판 목록에서 원글 바로 아래에 붙어 보입니다.
- **후기 #3 (칭찬 후기)**: 댓글 1번으로 올라가, 후기 화면 아래에 줄바꿈까지 그대로 보입니다.

**등록하며 드러난 것 (고침)**
- **답글 줄바꿈**: 답글은 게시판 글 본문(HTML)이라 줄바꿈이 사라지고 한 문단으로 붙어 보였습니다. 그래서 답글을 올릴 때 특수문자를 이스케이프하고 줄바꿈을 `<br>`로 바꾸도록 고쳤습니다(`toArticleHtml`). 댓글은 카페24가 직접 바꿔 주므로 그대로 둡니다.
  - 이미 올린 답글 #29는 대표 승인으로 본문만 HTML 판으로 바꿨습니다(`PUT /admin/boards/6/articles/29`). 지금은 인사, 세 문단, 서명이 다섯 줄로 나뉘어 보이고, `<br>` 글자가 그대로 드러나지도 않습니다.
- **미답변 판단**: API로 답글을 달아도 원글의 `reply_status`가 바뀌지 않았습니다(null 그대로). 그래서 "같은 목록 안에 답글이 달린 원글은 답한 것"으로 판단하도록 고쳤습니다. 이제 #2는 미답변 목록에 다시 나오지 않습니다.
- **후기 미답변**: 후기는 댓글이 달렸는지 목록만으로 알 수 없습니다. 지금은 문의함 DB에 이미 있는 후기를 다시 넣지 않는 것으로만 막습니다. DB를 새로 만들면 댓글을 단 후기도 다시 불러옵니다.
- **시험**: 카페24 클라이언트 시험 4개를 더해 94개입니다. 가짜 fetch로 실제 응답 모양을 흉내 냅니다.
